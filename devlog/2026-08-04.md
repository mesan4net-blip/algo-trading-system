### Deliberate deviations (documented in the file header, numbered 1-8)
1. **HTF alignment.** Defaults to the last CLOSED higher-timeframe bar, which
   matches Pine's HISTORICAL behaviour under `lookahead_off` and never
   repaints. Pine's realtime behaviour (developing bar) is available via
   `HTF_UseDevelopingBar = true`.
2. **Gap filter off-by-one is INHERITED, not introduced.** Because
   `lookahead_off` returns the last closed daily bar, the Pine's `day_open` /
   `day_pclose` are yesterday's open and the day-before's close — so on a new
   day it tests the PREVIOUS day's gap, not today's. Reproduced faithfully.
   NOT fixed here unilaterally: if unintended it is a Pine bug and must be
   fixed there first so both stay in step.
3. No transparency in MT4 — layers separated by bar width instead of opacity.
4. No wicks — MT4 allows only 8 drawn buffers; three bodies + stop line take
   seven. Pine default is `show_wicks = false`, so default view is unchanged.
5. `ticker.standard()` wrapper dropped — MT4 charts are always standard OHLC.
6. Daily cutoff uses BROKER SERVER time, not exchange time (no DST calendar).
7. EMA seeded from first raw value, not an SMA. Converges within ~30 bars at
   len 4/8; `WarmupBars` (default 100) blocks signals well past that.
8. Stop plots as a plain line, not a stepline (MT4 has no stepline).

### One guarded edge case
Pine's trail does `math.max(stop, anchor)`. With an Eligible-SHA trail anchor
and nothing eligible, the anchor is `na`, so `math.max` returns `na`, the stop
becomes `na`, and the trade freezes (`not na(stop_level)` fails forever after).
The port guards this: if the trail anchor is NA the trail update is skipped and
the existing stop is kept. This is a behavioural difference from the Pine in
that specific configuration. Flagged, not silently absorbed.

## Update — FX adaptation

### Why
Reviewed the port against spot FX rather than equities. Two real defects found,
plus two caveats that are documentation rather than code.

### Audited and found already correct (no change)
- 4-digit vs 5-digit brokers, and 2/3-digit JPY quoting — `Digits` is read from
  the symbol, never assumed. No hardcoded decimal places anywhere.
- Broker symbol suffixes (`EURUSD.m`, `EURUSDpro`) — everything routes through
  `Symbol()`.
- No assumed tick size, contract size or point value.

### Defect 1 — percent-of-price distorts across pairs
`0.10%` is 6.5 pips on AUDUSD at 0.6500 and 15 pips on USDJPY at 150.00, while
their daily ranges are nowhere near 2.3x apart. Percent is the right normaliser
on equities, not on FX: it over-buffers JPY crosses and under-buffers AUD/NZD.

FIX: added `DistanceUnit` (Percent / Pips). In Pips mode, stop buffer, min stop
distance, break-even offset and trail buffer take pip inputs
(`SlBufferPips`, `MinStopPips`, `BeOffsetPips`, `TrailBufferPips`).
`PipSize()` returns `Point*10` on 5- and 3-digit brokers and `Point` otherwise,
so 4-digit, 5-digit and JPY pairs all take the same number.
Default stays Percent, so Pine parity is unchanged unless switched.

### Defect 2 — bid-only charts understate short stop hits
MT4 draws BID. A short's stop executes on the ASK, so a short can be stopped
out when ask crosses the level while the bid high never touched it. On a 10-pip
stop with a 1.5-pip spread that is a 15% error on risk.

FIX: added `ShortsPaySpread` (default false). When true the short stop-hit test
becomes `High + spread >= stop` (hard stop) or `Close + spread >= stop`
(close-based). `SpreadPipsOverride` pins a fixed spread; 0 uses the live broker
spread. Scope deliberately limited to the stop-hit test only — entry fills and
the R calculation stay bid-based exactly as in the Pine. Widening it to fills
would be a second, unverified change.

KNOWN LIMITATION: with `SpreadPipsOverride = 0` the *current* spread is applied
to historical bars, since MT4 has no reliable historical spread. For a
repeatable historical comparison against the Pine, set a fixed override.

### Caveats documented, not coded
- The gap filter is nearly inert on spot FX (24/5, only the Sunday open gaps),
  the daily boundary is broker server midnight rather than any market close,
  and a short Sunday D1 bar can both fake a new day and distort the gap maths.
  Treat GapThresh as a weekend filter or leave it at 0.
- The daily cutoff is server time with no DST tracking. Most FX brokers shift
  their server offset with US daylight saving, so a fixed hour drifts against
  London and New York twice a year. No exchange close on spot FX to anchor to.
